# Google Drive 予算連携 — 運用手順書（非エンジニア向け）

最終更新: 2026-05-11 (JST)

この文書は **予算を入力・更新する担当者** と **運用責任者** が、日々の作業とトラブル時の判断に使う手順書です。  
技術的な全体像は別紙 **[`GOOGLE_DRIVE_BUDGET_SYNC_DESIGN.md`](./GOOGLE_DRIVE_BUDGET_SYNC_DESIGN.md)** を参照してください（**日次予算の「進行日」JST 5:00** とシート同期の違いは同文書 **§3.1**）。

---

## 1. この連携でできること

- **Google スプレッドシート**に予算を書き込むと、自動的に **売上分析画面（analytics）** や **LINE のレシート返信に使う予算** に反映される想定です。
- 担当者は **管理画面を開かなくても**、慣れたスプレッドシートだけで予算を更新できます（実装後の前提）。

---

## 2. 事前に決めておくこと（導入時・1回だけ）

次の項目は **情報システム担当または開発担当** と一緒に決めます。予算担当だけでは設定できない場合があります。

| 項目 | 内容 |
|------|------|
| 予算用スプレッドシート | どの Google ドライブ上のどのファイルを「正」とするか |
| 編集できる人 | 予算担当・承認者のみに限定する |
| 店舗の識別子 | シートの「店舗キー」列に、システム側と同じ値を書くルール |
| 反映の確認方法 | analytics で該当月・該当店舗を開いて予算が合うか |
| 連絡先 | 反映されない・エラーが出るときの窓口（メール・チャット） |

---

## 3. スプレッドシートの書き方（日々の作業）

### 3.1 使うシート

- メインの表（例: **`monthly_budgets`**）に、店舗ごと・月ごとの行を書きます。
- 店舗名の別名をまとめる表（例: **`store_mapping`**）がある場合は、そこに従います。

### 3.2 1行に書く内容（イメージ）

次のような列がある想定です（列名は実装時に確定します）。

| 書くこと | 例 | 注意 |
|----------|-----|------|
| 対象月 | `2026-05` | 必ず `年-月` の形（ハイフン付き） |
| 店舗名 | 店の通称 | 社内で通じる名前でよい場合があります |
| 店舗キー | システムと同じ文字列 | **ここが違うと別店舗に入る**ので要確認 |
| 月間予算（円） | `2000000` | カンマなしの整数が安全 |
| 平日・休日前・休日の比率 | 数字 | 運用ルールに従う（詳細は開発担当資料） |
| 休業日 | `2026-05-10,2026-05-11` | カンマ区切り。対象月の日付だけ |
| 有効フラグ | `TRUE` / `FALSE` | **`TRUE` の行だけ**が同期対象になる想定 |

### 3.3 よくある入力ミス

- **月の形式が違う**（`2026/05` や `2026年5月` だけ、など）→ ルールに合わせ直す。
- **店舗キーが空・誤字** → 別店舗に入ったり反映されないことがある。
- **予算が空・マイナス・文字** → その行はスキップされ、ログに残る想定。
- **休業日が別の月の日付** → その日は無視されるか、エラーになる想定。

## 4. 更新したあとにやること（確認チェックリスト）

実装後、次を **自分で確認** できると安心です。

1. スプレッドシートを保存した（自動保存でも可）。
2. **数分待つ**（自動同期の間隔がある場合）。
3. **売上分析（analytics）** を開き、  
   - 店舗  
   - 対象月  
   を選んで、**月間予算・日別の数字**が意図どおりか見る。
4. 必要なら **テスト用のレシート** を LINE に送り、**【予算】ブロック**の数字が期待どおりか見る。

**日次予算差（表・KPI・LINE）の「今日」**は暦の 0 時ではなく **JST 5:00 で切り替わります**。早朝に analytics を見て「当日の差がまだ 0」の場合は仕様どおりのことがあります。詳細は **`docs/RECEIPT_ANALYSIS_POLICY.md` 8.0** と **`docs/ANALYTICS_RECEIPT_SALES_AND_BUDGET.md`** 冒頭を参照してください。

すべて合っていれば、通常は作業完了です。

## 5. 月次・年次のおすすめルーティン

| タイミング | 作業 |
|------------|------|
| 月初 | 新しい月の行を追加し、`enabled` を `TRUE` にする |
| 月初 | 前月の行を `FALSE` にするか、運用ルールに従う |
| 四半期 | 店舗キー・店舗名の表（mapping）が古くなっていないか見直す |
| 人員交代時 | スプレッドシートの共有設定を見直す |

## 6. うまくいかないとき（最初に自分で見る場所）

実装によって名前は変わりますが、次のような **ログ用シート** がある想定です。

- **`sync_log`**（または同等）  
  - いつ・何行目・成功/失敗・メッセージ

**ログに「失敗」と出ている行**は、その行の入力を直してから再保存します。

---

## 7. トラブル別の対応（目安）

| 状況 | まず試すこと | それでもダメなら |
|------|----------------|------------------|
| analytics に反映されない | 該当行の `enabled` が `TRUE` か、月・店舗キー・予算が空でないか確認 | 窓口へ。ログのスクリーンショットを添付 |
| 一部の店だけおかしい | その店の **店舗キー** が他行と一致しているか確認 | 窓口へ |
| 通知で「エラー」と来た | ログシートの最新行を確認し、指摘された列を修正 | 窓口へ |
| 数字を間違えて送ってしまった | **スプレッドシートを正しい値に直して保存**（上書き同期の想定）。履歴から戻せるなら検討 | 重大なら窓口へ |

---

## 8. セキュリティ・権限（担当者が意識すること）

- 予算シートの URL を **社外に送らない**。
- **編集権限**を必要以上に広げない（閲覧のみの人は閲覧だけ）。
- 「共有リンク：誰でも編集」は **使わない**。

詳細な技術設定は開発・情シス担当が行います。

---

## 9. 用語の簡単メモ

| 用語 | 意味（ざっくり） |
|------|------------------|
| 店舗キー | システムが店舗を識別するための固定コード。スペルミスに注意。 |
| 同期 | スプレッドシートの内容を、サーバー側の予算データに反映すること。 |
| upsert | 「なければ新規、あれば上書き」という更新のしかた。 |
